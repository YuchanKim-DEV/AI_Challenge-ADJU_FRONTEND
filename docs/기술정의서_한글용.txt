8-5. 주요 기술 과제 및 해결

다중 NIC 환경의 비대칭 라우팅

[표] 아래 블록 선택 → 한글 메뉴 [입력] > [표] > [문자열을 표로] (탭 구분)
구분	내용
증상	외부에서 웹 접속 시 응답 없음. 관리 접속과 서버 내부 호출은 정상
원인	서버에 네트워크 인터페이스가 2개이며 공인 IP가 기본 경로가 아닌 인터페이스에 매핑됨. 요청은 정상 수신되나 응답이 다른 경로로 나가 중간에서 폐기
추가 요인	컨테이너 네트워크 변환(NAT)을 거친 응답은 출발지 주소 기반 정책 라우팅 규칙에 적용되지 않음
원인 규명	패킷 캡처(tcpdump)로 요청·응답 경로 불일치를 직접 확인
해결	연결 단위 표시(connection mark)를 부여하여 응답이 들어온 경로로 나가도록 강제. 컨테이너 네트워크 경로를 라우팅 테이블에 추가
영구화	서비스로 등록하여 재부팅 시 자동 적용. 설정 삭제 후 복원 테스트로 검증 완료

동일 출처 프록시 구조

프론트엔드와 API 서버가 분리된 구조에서는 통상 브라우저 교차 출처 제약(CORS) 설정이 필요하다.
리버스 프록시를 두어 브라우저 관점에서 단일 출처가 되도록 구성함으로써,
별도 설정 없이 동작하며 동시에 AI 서버를 외부에 노출하지 않는 효과를 얻었다.

- 보험과 무관한 입력에 대한 사전 안내

를 적용하여 서비스 안정성을 확보하였다.
